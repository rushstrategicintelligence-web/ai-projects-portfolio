## How Projects Are Documented

Each substantial project should document:

### Problem
What problem or question initiated the project?

### Approach
How was the problem broken down?

### System / Solution
What was designed or built?

### My Role
What did I research, design, structure, implement, coordinate, or validate?

### AI's Role
Where did AI contribute to research, development, generation, analysis, or iteration?

### Tools
What technologies, models, platforms, or workflows were involved?

### Outcome
What exists now that did not exist before?

### Limitations
What does the current implementation not solve?

### Next Steps
Where could the project go next?

## Asset Documentation Standard

Individual portfolio assets can be recorded in the Master Asset Index using a consistent metadata structure:

| Field | Purpose |
| --- | --- |
| Asset ID | Stable identifier |
| Asset Name | Human-readable title |
| Type | Framework, app, prompt, report, workflow, etc. |
| Project | Parent project or independent |
| Status | Active, complete, prototype, archived |
| Description | What the asset does |
| Tools | Technologies or AI tools involved |
| Location | Repository path |
| Related Assets | Connected artifacts |
| Last Updated | Most recent meaningful revision |

This makes the repository expandable without sacrificing discoverability as the number of projects and artifacts grows.
